![读者在群里提问如何在 Codex 中生图](/images/codex-image-generation/figure-01.webp)
![读者提到自己尝试生图时遇到的问题](/images/codex-image-generation/figure-02.webp)

这个问题比我想象中多。

有人 ChatGPT Plus 都开了，Codex 也装好了，写代码、读文件都能用，一到生成图片这里就卡住。

甚至有人跟我说：

**我都充 Plus 了，怎么感觉生图还没豆包好用？**

地狱笑话了哈哈哈。

还有人问我另一个需求。

他做电商，手里有商品原图，想把图片丢给 Codex，让 Codex 分析商品，再生成一整套电商详情图。

还有一种需求：

**我一篇文章要十几张配图，能不能让 Codex 一次给我生完？**

都可以。

今天这篇，我就从 Codex 怎么生成第一张图片开始，把参考图生图、电商详情图、批量生图这几个问题走一遍。

如果你已经装好了 Codex，但是从来没用它生成过图片，这篇可以从头跟着做。

## 一、先搞懂：GPT Image 2、imagegen、image_gen 到底是什么？

这里很多人第一步就绕晕了。

你可能会看到三个名字：

**GPT Image 2.5 、 imagegen  、 image_gen**

看着差不多，但不是一个东西。

GPT Image 2 （现在最新版是 image 2.5）是 ChatGPT 的图片生成模型。

但是我们今天不是写 API 教程。

我们是在 Codex 里面生图。

Codex 里有一个专门处理图片生成任务的 Skill，名字叫：

`imagegen`

![Codex 输入框中的 imagegen 技能](/images/codex-image-generation/figure-03.webp)

这个 Skill 再去调用 Codex 当前环境里的图片生成能力。

所以对于普通用户，我觉得不用记那么多东西。

你记住一句就够了：

**在 Codex 里想生成图片，可以让它调用 `/imagegen`。**

ChatGPT Plus/pro 用户，可以从 Codex 里完成图片生成（目前，codex中调用image 2.5，仅支持plus，pro用户使用）

所以我们从最简单的一张图开始。

## 二、Codex 怎么生成第一张图片？

我建了一个新的文件夹。

比如：codex-image-test

![在 Codex 中选择本地项目](/images/codex-image-generation/figure-04.webp)

![创建 codex-image-test 项目](/images/codex-image-generation/figure-05.webp)

然后用 Codex 打开这个文件夹。

![打开项目后的 Codex 对话框](/images/codex-image-generation/figure-06.webp)

接着，我给它一句话：

> 使用 `/imagegen` 帮我生成一张微信公众号文章首图。
>
> 主题：Codex 生成图片教程。
>
> 画面需要体现 Codex、AI 图片生成、批量图片生产。
>
> 比例 2.35:1。
>
> 白色浅色背景，不要大面积蓝紫渐变，不要科技发光风。
>
> 生成完成后保存到当前项目的 `images` 文件夹。

发出去之后，让 Codex 执行。

![输入公众号首图的生成要求](/images/codex-image-generation/figure-07.webp)

然后codex就会自动调用 image gen 这个skill来生成

![Codex 返回生图结果和保存位置](/images/codex-image-generation/figure-08.webp)

如果当前环境里的图片能力可用，你会看到 Codex 开始处理图片任务。

最后图片会被保存下来。

![生成的公众号文章首图](/images/codex-image-generation/figure-09.webp)

完成！到这里，第一个问题已经解决了：

**Codex 可以生成图片。**

而且和在 ChatGPT 对话框里生图有一个很大很大的区别。

Codex 是工作在项目里的，它可以管理文件，可以读取你的文章。

可以创建文件夹，可以按照规则命名图片。

也可以把十几张图片放进同一个目录里。

所以我认为，Codex 生图的价值，不在于：

> 给我画一只猫。

这种任务在 ChatGPT、豆包、即梦里都可以做。

Codex 更适合的是：**围绕一个项目生产一系列图片！**

比如公众号配图；电商素材；网站图片；游戏素材；产品 UI 素材；科研流程图

这才是它适合干的事情。

## 三、Codex 怎么参考一张图片生图？

接下来进入第二种情况。

手里已经有一张图片。

想让 Codex**参考这张图片生成新的图片，**这个需求也很常见。

这里我拿电商图片举例：

比如我现在有一张商品图。

![用于参考生图的懒人沙发原图](/images/codex-image-generation/figure-10.webp)

某宝随便找的一张做测试哈哈。

把商品图放进项目里。

比如：

![将沙发图片放入项目文件夹](/images/codex-image-generation/figure-11.webp)

然后不要上来就跟 Codex 说：

> 给我生成一个电商详情页。

我不建议这么做，因为这一步，Codex 连你的商品是什么都还没有梳理。

我会分两步。

第一步，只让它看图。

我给它：

> 读取 `懒人沙发.png`。
>
> 不生成图片。
>
> 分析图片中的商品。
>
> 告诉我：
>
> 商品是什么；
>
> 商品主体颜色；
>
> 外观结构；
>
> 图片中可以确认的材质和细节；
>
> 可以用于电商展示的卖点；
>
> 图片中无法确认的信息不要补充。
>
> 最后给我一份商品视觉分析。

这里有一个点我觉得很重要：

**不要让 AI 编商品参数。**

比如一张杯子的图片。

AI从图片里能看出来它是黑色、带把手、有盖子。

但它看不出来，容量是不是 500ml，保温是不是 12 小时。

这些不要让它猜。

电商图最怕的不是不好看，是商品都变了。

所以我会让 Codex 把：**看得到的，和看不到的，分开。**

![Codex 分析沙发参考图和商品特点](/images/codex-image-generation/figure-12.webp)

分析完成之后，再进入生图。

## 四、进阶：我让 Codex 用一张商品图，做一套电商详情图

这个就是今天文章里我觉得最好玩的一个部分。

也是之前有人来问我的需求：

> 能不能上传一张商品图，然后让 Codex 分析，再帮我生成电商详情图？

可以。

而且我的思路不是让它生成一张长图。

而是：**先规划，再拆图，再一张一张生成。**

因为一张电商详情页里面，本来就不是一张图。

它可能包含：产品首屏。核心卖点。使用场景。细节展示。尺寸信息。材质介绍。购买理由。

所以我会让 Codex先做一份图片规划。

我给它：

> 基于刚才对商品图片的分析，帮我设计一套电商商品详情图。
>
> 先不要生成图片。
>
> 以国内电商详情页的阅读习惯规划图片。
>
> 每一张图片解决一个问题。
>
> 图片中只能使用已经确认的商品信息。
>
> 对无法从图片确认的尺寸、参数、材质、功能，不允许编造。
>
> 输出每一张图的：
>
> 图片编号；
>
> 图片目的；
>
> 画面结构；
>
> 主文案；
>
> 商品展示方式。
>
> 整套图片保持同一套视觉语言。

![发送生成电商详情页的要求](/images/codex-image-generation/figure-13.webp)

然后 Codex 会给出一份方案。

![Codex 返回沙发详情图的分图方案](/images/codex-image-generation/figure-14.webp)

我看完方案以后，再让它开始生成。

> 按照刚才确定的电商详情图方案开始制作。
>
> 使用 `$imagegen`。
>
> `懒人沙发.png` 作为商品参考图。
>
> 商品主体必须保持一致。
>
> 保留商品的颜色、结构、比例、Logo 和可见细节。
>
> 不允许自行增加商品功能。
>
> 每个模块生成一张独立图片。
>
> 图片保存到：
>
> `image/`
>
> 文件按照下面格式命名：
>
> `01-cover.png`
>
> `02-selling-point.png`
>
> `03-scene.png`
>
> 后续顺延。
>
> 每生成一张图片，检查商品主体有没有发生变化。

![按方案分批执行商品图生成任务](/images/codex-image-generation/figure-15.webp)

这一步就是 Codex 和普通生图工具拉开区别的地方。

它不是只负责画图，它还在管理这一个任务。

商品原图放在哪里，要做几张，每张负责什么。叫什么名字。

放在哪个文件夹，上一张和下一张的风格怎么保持。

都可以写进任务里。

![同一款沙发生成的四张商品配图](/images/codex-image-generation/figure-16.webp)

我觉得这个案例还能继续扩。

比如你做淘宝、闲鱼、拼多多、小红书电商，都可以改。

甚至还可以让 Codex 在生成结束后，给你创建：

```text
ecommerce-detail/
├── 01-cover.png
├── 02-selling-point.png
├── 03-scene.png
├── 04-detail.png
├── 05-material.png
└── README.md
```

README 里面写清楚每张图片的用途。

这就从生图，变成了一套素材生产流程。

## 五、进阶：Codex 怎么批量生成图片？

接下来就是另一个被问得多的问题。

**怎么批量生图？**

比如我每天写公众号。

一篇文章里面可能需要很多张图片：

让我自己一张一张写提示词，我也烦。

所以我现在更倾向于把文章交给 Codex。

让它自己规划整篇文章需要什么图。

比如我把今天这篇文章保存成：

```text
article.md
```

然后给 Codex：

> 阅读 `article.pdf`。
>
> 我要给这篇公众号文章制作 10 张配图。
>
> 暂时不要生成。
>
> 根据文章内容规划 10 张图片。
>
> 每张图片必须对应文章中的一个位置。
>
> 不要为了凑数量生成重复信息。
>
> 比例以 2.35:1 为主。
>
> 先输出图片规划表。

![Codex 根据文章列出的配图规划表](/images/codex-image-generation/figure-17.webp)

我会先看一遍它规划的图片。

这里很重要。

**不要让它一拿到文章就开画。**

因为如果规划都不对，后面十张图片全得重做。

所以先确定：

哪十张？每张讲什么？放哪？

规划没有问题之后，再给它第二条。

> 按照刚才确定的 10 张图片方案执行。
>
> 使用 `/imagegen` 生成图片。
>
> 每张图片独立生成。
>
> 不要生成一张包含 10 个分区的大图。
>
> 全部保存到：
>
> `article-images/`
>
> 按照文章顺序命名：
>
> `01-cover.png`
>
> `02-xxx.png`
>
> `03-xxx.png`
>
> ……
>
> 每完成一张，检查图片文件是否已经保存，再继续下一张。

然后你就可以让它开始跑了。

![Codex 为文章生成的配图预览](/images/codex-image-generation/figure-18.webp)

生成完成以后，你会得到一个整理好的图片文件夹。

![项目文件夹中的 article-images 输出目录](/images/codex-image-generation/figure-19.webp)

这就是我理解的：**Codex 批量生图。**

不只是一次生成很多张。

而是：**读内容 → 规划图片 → 调用图片模型 → 保存文件 → 编号管理。**

这一套才有用。

## 六、批量生成几十张、上百张图片怎么办？

前面的批量生图，适合公众号、电商详情页、网站素材这些场景。

十张二十张这种数量，用 Codex 的图片能力一张一张处理就够了。

但是还有一种情况。

比如：100 个商品 SKU。

这种量级，再让 Codex在一个会话里一张一张跑，就不是一个舒服的方案了。

这时候才需要考虑：**API 批量生成。**

GPT Image 2 提供 API。

Codex 的 imagegen Skill 里面也有批量生成相关的脚本能力。

这种方式会涉及：OpenAI API Key。

调用额度；批处理文件；脚本；模型参数。

这已经属于另一套玩法，所以这篇我不往里面展开。

否则一篇给小白看的 Codex 生图教程，写到最后变成 Python API 教程了。

如果只是：公众号十几张图。一套电商详情图。一批网站素材。

Plus 用户先把前面的工作流跑通就够了。

![小批量生图与 API 批量任务的适用场景](/images/codex-image-generation/figure-20.webp)

## 七、为什么我的 Codex 不会生成图片？

这个问题我也单独说一下。

因为有人可能跟着上面的指令输入：

> 使用 `/imagegen`。

结果 Codex告诉你，当前环境缺少可访问的方式。

![Codex 提示当前环境无法使用生图工具](/images/codex-image-generation/figure-21.webp)

这时候别一直改提示词。

先让 Codex 自己检查：

> 检查当前 Codex 环境。
>
> 告诉我：
>
> 是否存在 `imagegen` Skill；
>
> 当前会话是否可以调用图片生成工具；
>
> 如果不能调用，告诉我缺少的是 Skill、图片工具还是 API 配置。
>
> 不要生成图片。

让它先诊断。

因为**Skill 存在，不代表当前会话的图片工具一定处于可调用状态。**

还有一种可能是因为，输入错误，应该输入的是：

/imagegen

## 八、Codex 生图和 ChatGPT、豆包有什么区别？

写到这里，回到开头那个问题。

有人说：

> 我都开 Plus 了，为什么感觉 Codex 生图还没豆包好用？

如果你只是想玩玩

那我觉得你完全没必要用 Codex。

ChatGPT、豆包、即梦这种对话式产品用起来更顺手。

Codex 的优势在另一边。

比如我今天演示的：

给它一篇文章让它规划十张图。

生成之后自动命名，然后保存，再修改第三张，重新生成第五张。

或者给它一张商品图，分析商品，规划详情页，生成整套素材。

最后整理进项目文件夹。

这才是 Codex 生图让我觉得有意思的地方。

**它是把图片生成能力放进了一个 Agent 工作环境里。**

![Codex 生图工具可用性的排查步骤](/images/codex-image-generation/figure-22.webp)

图片只是整个任务中的一个环节。

## 九、再往前一步，图片也可以变成 Codex 工作流

到这里，我觉得就可以开始发散了。

比如我每天写完公众号以后，可以把文章扔给 Codex：

让codex读取正文并且规划配图，最后生成配图。

那以后每篇文章的结构都可以变成：

```text
2026-09-07-codex-image/
├── article.md
├── images/
│   ├── 01-cover.png
│   ├── 02-imagegen.png
│   ├── 03-workflow.png
│   └── 04-summary.png
└── prompts/
```

![从文章内容到生成配图的工作流程](/images/codex-image-generation/figure-23.webp)

再比如电商。

商品原图进来，Codex 分析，生成详情图，生成广告素材，生成小红书封面，生成朋友圈海报。

一份商品素材，可以继续拆成多个平台使用。

![将一份商品素材拆成多个平台的图文内容](/images/codex-image-generation/figure-24.webp)

这个时候，GPT Image 2 就不只是一个生图模型了。

它成了 Codex 工作流里的一个能力。

这也是我最近用 Agent 类工具越来越强的一种感受：

**很多以前我们需要在几个软件之间来回切换的事情，现在开始能放进同一个任务里完成。**
